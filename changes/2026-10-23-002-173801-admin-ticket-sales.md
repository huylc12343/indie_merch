# Admin sidebar and ticket sales

- Created: 2026-10-23T17:38:01+07:00
- Updated: 2026-10-23T17:42:23+07:00

## Request

Add a sidebar to admin, integrate event/ticket management, and implement ticket sales like merch with Directus, mock, and PostgreSQL sources configured through env.

## Changes

- Added a responsive admin sidebar for merch orders, products, events/ticket tiers, and ticket orders.
- Added `/tickets`: event/tier selection, buyer details, coupon, shared QR simulation, success, and one unique code/QR per purchased ticket.
- Added event and tier management plus ticket order/code visibility in admin.
- Added `TICKET_DATA_SOURCE` and configurable Directus collection names. Directus imports catalog data into SQL; PostgreSQL remains authoritative for reservations, orders, and issued tickets outside browser demo mode.
- Reused merch reservation/payment transactions with explicit catalog and event checks. Added event, catalog-kind, and issued-ticket schema/seed data.
- Extended browser demo storage to preserve existing merch data, initialize sample events/tiers, and isolate merch/ticket orders and stock.

## Decisions and limits

- Merch and tickets share order/reservation mechanics; ticket products and orders are distinguished by kind and event ID. A ticket order can contain tiers from only one event.
- Existing browser demo data is migrated without deleting merch orders. Browser data remains scoped to that browser and Preview hostname.
- Google login and payment are still explicit demos on Preview. Issued ticket QRs identify tickets; admission scanning and email delivery are outside this request.
- Local PostgreSQL and npm registry/GitHub networking remain unavailable. Live SQL/Directus integration must be verified against configured services; the Preview uses mock data.
